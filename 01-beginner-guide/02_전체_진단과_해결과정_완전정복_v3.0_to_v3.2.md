# 02. 전체 진단과 해결 과정 완전 정복 (`v3.0` → `v3.2.0`)

> **이 문서의 핵심**: *"7 Hz인데 왜 파동이 정신없이 움직이나요?"*, *"볼륨 100%가 빠졌고 120%까지 찌그러짐 없이 올리고 싶어요"*, *"미니바에서 전체 버튼이 안 눌러져요"*, *"저장소가 너무 어지러워요"* 같은 **실제 사용자의 문제 제기 7가지**가 어떤 **원인 진단(Diagnosis)** 과 **엔지니어링 해결(Resolution)** 을 거쳐 지금의 `v3.2.0` 상용 스튜디오로 완성되었는지 한눈에 정리한 기록입니다.

---

## 분석 방법: MIA 11단계 전략 프레임워크 (`MIA Strategic 11-Stage Framework`)

모든 개선 작업은 추측으로 코드를 바로 고치지 않고 다음 흐름을 지켰습니다.
1. **사전 근거 조사(Stage 0 Web Deep Research)**: 공식 문서(Microsoft WASAPI/WPF, SemVer 2.0, Diátaxis, GitHub Docs) 확인.
2. **기획 · 대안 비교(Stage 1~4)**: 최소 2~3개 구현 방식을 비교해 안전성·품질·유지보수성 기준으로 최적안(`Go`) 확정.
3. **범위 고정 · 백업(Stage 5~8)**: 기존 Android 앱과 핵심 48개 프리셋 패리티(`Parity`, 호환 동일성)를 깨지 않도록 수정 범위를 잠금.
4. **구현 · 디버깅 · 자동 검증(Stage 9~10)**: 사람이 눈으로만 보고 끝내지 않고, **자동 자가진단 테스트(`--self-test`)** 와 **독립 감사**로 수치 검증.

## 7대 문제 진단 및 해결 사례 (`Structured Few-Shot Case Studies`)

> 아래 7개 사례는 모두 **`① 사용자 증상 → ② 초보자 눈높이 원인 진단(ELI10) → ③ 전문가 해결 설계(Deep-Dive) → ④ 실측 검증 증거 → ⑤ 체감 변화`** 의 5단계 구조로 통일되어 있습니다.

### 사례 1. 무거운 웹 래퍼 탈피 — 네이티브 Windows WASAPI 초경량 엔진 전환 (`v3.0`)

- **① 사용자 증상**: 웹 브라우저(Edge WebView) + Python 서버 방식으로 실행하면 메모리를 100 MB 안팎으로 차지하고, 창을 닫을 때 백그라운드 프로세스가 엉킬 위험이 있었습니다.
- **② 초보자 눈높이 원인 진단 (`ELI10` + 전문용어)**:
  - 기존 방식은 음악 플레이어 하나를 켜기 위해 **"인터넷 브라우저 한 채 + 통역사 서버 프로그램"을 같이 띄우는 것**과 같아 무거웠습니다.
  - 반면 Windows에 기본 탑재된 **`.NET Framework 4.8`(닷넷 프레임워크 4.8)** 과 **`WASAPI`(와사피, Windows Audio Session API — Windows가 소리를 사운드카드로 직접 보내는 표준 고속 통로)** 를 C# 네이티브 코드로 직접 다루면 중간 통역사 없이 사운드카드와 직통으로 대화할 수 있습니다.
- **③ 전문가 해결 설계 (`Deep-Dive`)**:
  - `02-apps/pc-windows-vorta-aegis/native/` 폴더에 C# 5.0 기반의 8개 독립 모듈 구축:
    - `WasapiAudioEngine.cs`: COM 인터페이스 기반 Shared-Mode 32-bit IEEE Float (`48 kHz`) 이벤트 구동 오디오 출력 + 시스템 기본 장치 자동 추적.
    - `AegisDspEngine.cs`: **`64-bit NCO`(Numerically Controlled Oscillator, 64비트 수치 제어 발진기 — 소수점 오차 없이 정현파 각도를 계산하는 디지털 파동 생성기)** 와 클릭음 방지 디클리커(De-clicker) 탑재.
    - `Program.cs` + `CompanionUi.cs`: `NotifyIcon` 트레이 백그라운드 상주(창 `×` 를 눌러도 소리 계속 재생, Global Hotkey/SMTC/토스트 비간섭).
- **④ 실측 검증 증거**:
  - 외부 SDK 설치 없이 `python 02-apps/pc-windows-vorta-aegis/install_pc.py` 한 줄로 Windows 기본 `csc.exe` 가 `VortaAegisPC.exe` (x64) 를 즉시 컴파일.
- **⑤ 체감 변화**: 브라우저 창 덩어리가 사라지고, 1초 만에 켜지는 가벼운 전용 PC 앱으로 탈바꿈했습니다.

### 사례 2. 창 크기 고정 해결 · 중앙 `GridSplitter` · `100% ~ 120%` 무왜곡 클린 증폭 (`v3.1` → `v3.2`)

- **① 사용자 증상**: 창 크기를 자유롭게 늘리거나 좌우 패널 폭을 원하는 대로 조절할 수 없고, 볼륨 버튼에 `100%` 가 빠졌으며 `120%` 까지 키웠을 때 소리가 찢어지지 않아야 합니다.
- **② 초보자 눈높이 원인 진단 (`ELI10` + 전문용어)**:
  - 소리를 100% 넘게 키우다 보면 음량 꼭대기가 천장(`1.0`)을 뚫고 납작하게 잘리는 **`하드 클리핑(Hard Clipping, 파형 꼭대기가 칼로 잘린 것처럼 뭉개져 귀가 아픈 잡음이 생기는 현상)`** 이 발생합니다.
  - 이를 막으려면 꼭대기에 닿기 직전에만 스펀지처럼 부드럽게 낮춰 주는 **`선형 피크 리미터(Linear Peak Limiter)`** 와, 천장에 **`-0.50 dBTP`(True-Peak, 디지털 샘플과 샘플 사이에서 순간적으로 튀는 실제 아날로그 피크 기준 `-0.50 dB` 여유 공간)** 안전선을 두어야 합니다.
- **③ 전문가 해결 설계 (`Deep-Dive`)**:
  - **자유 리사이즈 & 좌우 폭 조절**: `WindowChrome` 테두리 드래그(`400×540` ~ 전체화면, 좁으면 세로 컴팩트 모드 · 넓으면 2단 스튜디오 · `1080px` 이상이면 프리셋 카드 2열 배치) 및 중앙 **`GridSplitter`(그리드 스플리터, 좌우 패널 경계선을 마우스로 끌어 너비를 조절하는 구분 막대)** 와 `%LOCALAPPDATA%\VortaAegis\state_v3.json` 자동·수동 폭(`ConsolePaneWidth`) 기억 기능 추가.
  - **클린 증폭 (`AegisDspEngine.cs`, `PresetCatalog.cs`)**: 볼륨 6단 디텐트(`15% 영상` / `30% 작업` / `50% 병행` / `80% 단독` / `100% 최대(0.0 dB)` / `120% 증폭(+1.6 dB)`) 구현 및 하드 클리핑 코드(`vL = CLEAN_BOOST_CEILING`) 전면 제거 + `180 ms` 릴리즈 선형 리미터(`mLimGain`) 적용 + 초과 발생 횟수를 세는 `OvershootCount` 감시 계수기 도입.
- **④ 실측 검증 증거**:
  - `--self-test` 에서 **전체 64종 프리셋 × 3가지 출력 프로파일 = `192개 조합`** 을 `120%` 볼륨으로 렌더링해 **4× 큐빅 보간 트루피크 `<= -0.50 dBTP`** 와 **`OvershootCount == 0`** 통과.
  - `40 Hz`, `200 Hz`, `528 Hz`, `1000 Hz` **코히어런트 **`DFT`(Discrete Fourier Transform, 이산 푸리에 변환 — 소리 파동에 원치 않는 찌그러진 잡음 고조파가 얼마나 섞였는지 주파수별로 분리해 측정하는 수학 공식)** 검증**에서 **`THD+N`(Total Harmonic Distortion + Noise, 전고조파 왜율 및 잡음) < 0.1%`** 실측 통과.
- **⑤ 체감 변화**: 모니터 크기에 맞게 좌우를 넓히고 `120%` 증폭 버튼까지 올려도 날카로운 찢어짐 없이 단단하고 선명한 출력이 유지됩니다.

### 사례 3. *"7 Hz 대인데 왜 파동이 정신없이 찌글찌글한가요?"* — 실제 주파수 파동 정밀 스코프 (`v3.2`)

- **① 사용자 증상**: `P02 어지러움 · 균형 감각 방어 (7.00 Hz)` 를 재생했는데 화면의 노란색 오실로스코프 그래프가 천천히 출렁이지 않고 톱니처럼 자잘하고 정신없이 흔들렸습니다.
- **② 초보자 눈높이 원인 진단 (`ELI10` + 전문용어)**:
  - **거짓말이 아니라 실제로 그 빠른 파동이 스피커로 나가고 있었기 때문**입니다!
  - 앞서 설명했듯 작은 PC 스피커에서는 `7 Hz` 만 내보내면 소리가 안 들리므로, 앱이 **`144 Hz` 반송파(Carrier, 작은 스피커를 울려 주는 기본 운반 파동)** 를 같이 섞어서 내보내고 있었습니다.
  - 게다가 화면 창 길이가 **`74.7 ms`(밀리초, 0.0747초)** 로 너무 짧아서, `144 Hz` 물결이 한 화면에 `10개` 넘게 빽빽하게 겹쳐 보이고, `7 Hz` 의 거대한 1주기(`142.8 ms`)는 화면 밖으로 반 이상 잘려서 찌글거리는 선처럼 보인 것입니다.
  - 여기에 파동을 왼쪽 끝에서 출발시키는 **`트리거(Trigger, 파동이 일정 높이를 지나는 순간을 잡아 화면을 고정하는 카메라 셔터 기능)`** 가 단순 영점 통과만 잡아서 화면이 좌우로 흔들리는 현상까지 겹쳤습니다.
- **③ 전문가 해결 설계 (`Deep-Dive` in `AegisDspEngine.cs` & `CompanionUi.cs`)**:
  1. **이중 속도 링버퍼(`Dual-Rate Ring Buffer`)**: 기존 `48,000 Hz` 고속 링 외에, **32배 **`데시메이션(Decimation, 32샘플마다 저역 대역을 대표값으로 추려 1,500 Hz로 완만하게 기록하는 다운샘플링 기법)`** 전용 저주파 링(`SCOPE_LOW_RING_SIZE = 4096`, 최대 `2.73초` 보관)** 을 신설했습니다. 덕분에 `7.00 Hz` 도 3주기(`428.7 ms`)가 한눈에 들어옵니다.
  2. **보정 전 기본파 탭(`Pre-Compensation Fundamental Tap`)**: `CopyScopeSnapshotEx` 함수를 신설해 **"순수 기본 파동 (`7.00 Hz`)"** 과 **"144 Hz 반송파가 합쳐진 실출력 파형"** 두 갈래를 동시에 기록합니다.
  3. **동적 히스테리시스 상승 영점 트리거(`Hysteresis Trigger`)**: 작은 떨림에 오작동하지 않도록 문턱값을 둔 안정적인 셔터 알고리즘을 적용했습니다.
  4. **파형 전환 토글 버튼**: 그래프 우측 상단에 **`기본 파동 | 실출력 보기`** 버튼을 추가해 사용자가 원할 때 두 파형을 직접 비교할 수 있습니다.
- **④ 실측 검증 증거**:
  - `Program.cs` `--self-test` 6번 검증에서 `P02 (7.00 Hz)` 기준 저주파 링 샘플레이트 `1500.0 Hz` 정확 일치, 기본파 링 내 Zero-Crossing(영점 통과) 3주기 매끄러운 정현파 확인.
  - 실창 캡처 `assets/vorta_pc_v32_tall_7hz_scope.png` 에서 `7.00 Hz` 가 `428.7 ms (3.0주기) · 1.5kHz` 로 완벽한 매끄러운 S자 물결을 그림을 육안 확인.
- **⑤ 체감 변화**: `7.00 Hz` 를 켜면 교과서처럼 고요하고 부드러운 `7 Hz` 물결 3주기가 그려지고, 원하면 버튼 한 번으로 실제 스피커용 `144 Hz` 합성 파형도 비교할 수 있습니다.

### 사례 4. 상용 레퍼토리 다양화 가치판단 & 모듈형 확장 팩 (`Go — Pivot to Curated Modular Packs`, `v3.2`)

- **① 사용자 증상**: 프리셋 레퍼토리 시나리오를 다양화해서 실제 판매할 수 있는 상용 품질로 끌어올릴지 가치 판단하고, 향후 업데이트로 콘텐츠를 쉽게 늘릴 수 있게 설계해 달라는 요청입니다.
- **② 초보자 눈높이 원인 진단 (`ELI10` + 전문용어)**:
  - 무조건 숫자만 채우려고 무근거 시나리오 200개를 기존 리스트에 마구 섞으면 **모바일(Android)과 PC의 핵심 48개 기준표가 틀어지고 사용자도 길을 잃습니다**.
  - 대신 **핵심 48종(`Core 48`)은 100% 동일하게 지키고**, 게임의 확장팩(DLC)처럼 **`JSON`(제이슨, 사람이 읽기 쉬운 텍스트 설정 파일)** 파일 하나만 폴더에 넣으면 자동으로 새 프리셋 묶음이 추가되는 **레고 블록형(모듈형) 구조**로 만들면 가치와 업데이트 확장성이 동시에 극대화됩니다.
- **③ 전문가 해결 설계 (`Deep-Dive` in `PresetCatalog.cs` & `packs/`)**:
  - 시장 검증 가치판단 결과: **`Go — Pivot to Curated Modular Packs`** 채택.
  - 엄격한 **`Schema v1`(스키마 v1, 확장 팩 JSON 파일이 반드시 지켜야 하는 데이터 규칙표)** 설계: Android와 동일한 48종(`web/presets.json`, `P01`~`P48`) + PC 상용 프로 확장팩 `packs/vorta_pc_pro_pack_v1.json` 16종(`C01`~`C16`, 브라운 노이즈 `1/f²`, 2.8 kHz 롤오프 소프트 마스킹 등 추가) = **총 64종 기본 탑재**.
  - 앱 재빌드 없이 `%LOCALAPPDATA%\VortaAegis\packs\*.json` 에 파일만 넣고 `[팩 새로고침]` 을 누르면 즉시 로드(손상된 JSON이나 미래 버전 스키마 파일이 들어와도 앱이 죽지 않고 안전하게 건너뛰는 격리 로더 검증).
- **④ 실측 검증 증거**:
  - `Program.cs` `--self-test` 1번 검증에서 `48`종 코어 패리티 + `64`종 통합 로드 + 메모리 내 테스트(`65`종 정상 로드 및 손상/미래 스키마 2종 무오류 건너뛰기 `SkippedFiles.Count == 2`) 통과.
- **⑤ 체감 변화**: 기존 48종 사용자는 헷갈리지 않으면서 `PC Pro` 태그가 붙은 16가지 전문 시나리오(40 Hz 딥워크, 브라운 노이즈 심층 차폐 등)를 바로 쓰고 추후 팩 단위 업데이트도 가능합니다.

### 사례 6. 미니 플로팅 바 `"전체"` 복원 버튼 무반응 버그 Root Cause 분석 및 회귀 테스트 (`v3.2`)

- **① 사용자 증상**: 상단 `[미니 바]` 버튼을 눌러 화면 한쪽에 작게 띄운 상태에서 다시 원래 큰 창으로 돌아가려고 **`[전체]` 버튼을 클릭해도 창이 돌아가지 않고 반응이 없었습니다.**
- **② 초보자 눈높이 원인 진단 (`ELI10` + 전문용어)**:
  - 미니바는 제목 표시줄이 없는 디자인이라서, 배경 아무 곳이나 마우스로 잡고 창을 끌 수 있게 **`DragMove()`(드래그 이동 명령)** 를 걸어 두었습니다.
  - 그런데 Windows **`WPF`(Windows Presentation Foundation, Windows 화면을 그리는 기술)** 에서는 마우스를 **"누르는 순간(`MouseLeftButtonDown`)"** 과 **"떼는 순간(`MouseLeftButtonUp`)"** 이 따로 발생합니다.
  - 사용자가 `[전체]` 버튼을 딱 **누르는 순간**, 버튼이 *"잠깐! 이건 내 버튼 클릭이야!"* (`e.Handled = true`) 하고 외치지 않아서 이벤트가 배경 테두리(`outer`)로 올라갔고, **배경이 즉시 `DragMove()` 로 마우스 조종권을 낚아채 버린 탓에 마우스를 떼는 순간(`[전체]` 실행 신호 `MouseLeftButtonUp`)이 영원히 증발**해 버렸습니다.
- **③ 전문가 해결 설계 (`Deep-Dive` in `CompanionUi.cs` & `Program.cs`)**:
  - `MakeMiniChip`, `MakeMiniIconChip`, `mToggleBtn`, `mMuteBtn` 등 미니바의 모든 6개 버튼에 `MouseLeftButtonDown += (s, e) => { e.Handled = true; }` 를 추가해 배경의 `DragMove()` 가 가로채지 못하게 차단.
  - `WindowChrome.SetIsHitTestVisibleInChrome(..., true)` 를 모든 버튼과 볼륨 슬라이더(`mVolSlider`)에 지정하고, `outer.MouseLeftButtonDown` 에서도 `IsVisualDescendantOf(src, mVolSlider)` 검사를 추가.
  - 추가로 정보 영역(`info`) **더블클릭** 시에도 `SwitchToMiniMode(false)` 로 전체 패널 복원이 되도록 편의성을 이중 확보.
  - `Program.cs` 에 `internal Border RestoreFullButton` + `MiniBarTestController` 를 이용한 **자동 UI 클릭 회귀 테스트(`--self-test` 11번)** 를 심어 두어 다시는 같은 버그가 재발하지 않도록 못 박음.
- **④ 실측 검증 증거**:
  - `Program.cs` 11번 테스트: `RestoreFullButton` 에 `MouseLeftButtonDownEvent` 전달 시 `downArgs.Handled == true` 확인, 이어 `MouseLeftButtonUpEvent` 전달 시 `SwitchToFullCount == 1` 및 `LastMiniFlag == false` 어설션 통과.
- **⑤ 체감 변화**: 미니바의 `[전체]` 버튼(및 정보 영역 더블클릭)을 누르면 즉시 원래의 전체 스튜디오 창으로 깔끔하게 복귀합니다.
